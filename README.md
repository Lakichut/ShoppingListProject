# Документация за Docker оркестрация: Проект "ShoppingList"

Настоящото ръководство описва жизнения цикъл, изолирането и централизираното управление на трикомпонентното уеб приложение ShoppingList. Системата е реализирана чрез разпределена трислойна архитектура (3-tier), включваща клиентски интерфейс (React), приложен сървър (Node.js/Express REST API) и хранилище за данни (MongoDB). Всички елементи са конфигурирани за съвместна работа в напълно изолирана среда посредством Docker и Docker Compose.

---

## 1. Конфигурационна структура на директориите

```text
ShoppingList/
├── backend/                  # REST API компонент (Node.js & Express)
│   ├── logs/                 # Локално съхранение на системни лог файлове
│   ├── models/               # Схеми за управление на данните (Mongoose)
│   ├── app.js                # Инициализация на сървъра и връзка с базата данни
│   ├── Dockerfile            # Спецификация за изграждане на бекенд имиджа
│   └── package.json
├── frontend/                 # Потребителски интерфейс (React SPA)
│   ├── public/               # Публични ресурси и статични файлове
│   ├── src/                  # Изходен код на интерфейса
│   │   ├── components/       # Интерактивни компоненти за управление на списъка
│   │   ├── App.js            # Основен управляващ компонент
│   │   └── index.js
│   ├── Dockerfile            # Спецификация за изграждане на фронтенд имиджа
│   └── package.json
├── docker-compose.yml        # Главен конфигурационен файл за оркестрация
└── README.md                 # Техническа документация на проекта
```

## 2. Спецификация на отделните микроуслуги

### База данни (услуга: mongodb)
* **Технологична основа:** Използва официалния стабилен образ `mongo:latest`.
* **Контрол на достъпа:** Връзката е подсигурена чрез администраторско потребителско име и парола.
* **Постоянство на данните:** Интегриран е Docker обем (`data`), който гарантира, че въведените списъци и продукти се записват директно на хост машината и не се изтриват при спиране на контейнера.

### Приложен сървър (услуга: backend_image_ioan)
* **Технологична основа:** Базиран на Node.js среда за изпълнение с Express API слой.
* **Роля в системата:** Обработва REST API заявките от клиента за извличане, добавяне и изтриване на записи.
* **Управление на паметта:** Посредством именован обем се извършва запис на логовете в реално време, а вътрешните зависимости в `node_modules` са защитени от презаписване при локална разработка чрез анонимен обем.

### Клиентски интерфейс (услуга: frontend)
* **Технологична основа:** Интерактивно едностранично приложение (SPA), изградено с React.
* **Мрежови параметри:** Функционира на порт 3000 и изпраща асинхронни заявки към сървъра.
* **Динамична разработка:** Използва споделена директория тип bind mount (`./frontend/src:/usr/src/app/src`), позволяваща промените по кода да се отразяват моментално в контейнера без нужда от нов build.

## 3. Мрежова топология и интеграция

Връзката между микроуслугите е проектирана според актуалните DevOps практики:

* **Затворена мрежа:** Всички контейнери са асоциирани към изолирана bridge мрежа с наименование `list-products-network`.
* **Сервизна комуникация:** Вместо уязвими и динамични IP адреси, компонентите се откриват взаимно чрез вградената DNS система на Docker по имената на услугите от `docker-compose.yml`.
* **Връзка на бекенда с базата данни:** Контекстният низ за автентикация и свързване е дефиниран по следния начин:
```text
  MONGO_URL=mongodb://Ioan1234:IoanSecret@mongodb:27017/list-products?authSource=admin
  ```
  Името на хоста `mongodb` сочи директно към контейнера на базата данни в същата мрежа.

## 4. Ръководство за изграждане и внедряване

Следващите стъпки описват процеса по подготовка, компилиране, публикуване в Docker Hub профила `yoanlakov` и локалното стартиране на проекта.

### Стъпка 1: Автентикация в Docker Hub
Преди изграждане и изтласкване на образите е необходимо да влезете в профила си през терминала:
```bash
docker login
```
*(Въведете вашето потребителско име `yoanlakov` и парола/токен при подкана).*

### Стъпка 2: Изграждане и изтласкване на Бекенд компонента
Преминете в директорията на сървъра, компилирайте имиджа и го изпратете към отдалеченото хранилище:
```bash
cd backend
docker build -t yoanlakov/ioan-dockerfile-backend:latest .
docker push yoanlakov/ioan-dockerfile-backend:latest
cd ..
```

### Стъпка 3: Изграждане и изтласкване на Фронтенд компонента
Влезте в директорията на клиентското приложение и изпълнете същите команди, като спазвате изискването за малки букви в тага за пълна съвместимост:
```bash
cd frontend
docker build -t yoanlakov/ioan-dockerfile-frontend:latest .
docker push yoanlakov/ioan-dockerfile-frontend:latest
cd ..
```

### Стъпка 4: Локално стартиране на инфраструктурата
След като образите са налични и описани в конфигурацията, стартирайте цялата система в фонов режим (detached mode) от главната директория `ShoppingList`:
```bash
docker compose up -d
```
Docker Compose ще активира контейнерите в правилната последователност и ще потвърди стартирането на `frontend_container_ioan`, `mongodb` и `backend_container_ioan`.
