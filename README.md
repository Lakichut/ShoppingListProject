# 📦 Контейнеризация на проект "ShoppingList" с Docker Compose

Този проект демонстрира пълна контейнеризация на трикомпонентно уеб приложение за управление на бъдещи списъци за пазаруване (ShoppingList App). Архитектурата се състои от Frontend (React уеб интерфейс), Backend (Node.js/Express REST API) и База данни (MongoDB). Всички компоненти са конфигурирани да работят в изолирана виртуална среда и пълен синхрон чрез Docker и Docker Compose.

---

## ⚙️ Как работи всеки от компонентите

1. **База данни (`mongodb`):**
   * Използва официалния стабилен образ `mongo:latest`.
   * Конфигуриран е с администраторски достъп чрез потребителско име и сигурна парола.
   * Използва Docker Volume (`data`), за да гарантира персистентност на данните – въведените бъдещи покупки се пазят на хард диска и не се изтриват при спиране на контейнерите.

2. **Бекенд услуга (`backend_image_ioan`):**
   * Изградена на базата на Node.js и Express.
   * Предоставя REST API ендпоинти за извличане, добавяне и изтриване на елементи от списъка с продукти.
   * Записва системни логове от заявките в реално време посредством споделен обем `logs` и използва анонимен обем за `node_modules`, за да не се презаписват вътрешните пакети при локална разработка.

3. **Фронтенд услуга (`frontend`):**
   * Изгражда потребителския интерфейс (UI) и визуализира интерактивния списък.
   * Слуша на порт `3000` и комуникира асинхронно с Бекенд API-то.
   * Синхронизира локалните промени по кода в реално време чрез bind mount обвързване (`./frontend/src:/usr/src/app/src`).

## 🌐 Комуникация между услугите

Комуникацията в проекта е изградена изцяло според най-добрите Docker практики:
* **Изолирана мрежа:** Всички контейнери са свързани към обща виртуална мрежа от тип `bridge`, дефинирана като `list-products-network`.
* **DNS Резолюция по име на услуга:** Вътре в мрежата контейнерите комуникират помежду си не чрез динамични IP адреси, а директно чрез дефинираните имена на услугите в `docker-compose.yml`.
* **Връзка към Базата данни:** Бекендът се свързва успешно към MongoDB чрез следния стандартизиран URI адрес:
  ```text
  MONGO_URL=mongodb://Ioan1234:IoanSecret@mongodb:27017/list-products?authSource=admin
  ```
  *Хостът `mongodb` съвпада точно с името на контейнера за базата данни, осигурявайки перфектна вътрешна връзка.*

## 🛠️ Инструкции за изграждане и стартиране

Процесът по подготовка, изграждане, публикуване на образите в **Docker Hub** под профила `yoanlakov` и локалното стартиране се извършва чрез следните стъпки:

### 1. Аутентикация в Docker Hub
Преди изграждането и качването на образите е извършено влизане в личния Docker Hub профил през терминала:
```bash
docker login
```
*(Въвежда се потребителско име `yoanlakov`)*

### 2. Подготовка и публикуване на Бекенд компонента
Влиза се в папка `backend`, изгражда се образът и се изтласква към отдалеченото хранилище:
```bash
cd backend
docker build -t yoanlakov/ioan-dockerfile-backend:latest .
docker push yoanlakov/ioan-dockerfile-backend:latest
cd ..
```

### 3. Подготовка и публикуване на Фронтенд компонента
Влиза се в папка `frontend`, изгражда се потребителският интерфейс изцяло с малки букви в тага, за да се осигури съвместимост с правилата на Docker:
```bash
cd frontend
docker build -t yoanlakov/ioan-dockerfile-frontend:latest .
docker push yoanlakov/ioan-dockerfile-frontend:latest
cd ..
```

### 4. Стартиране на инфраструктурата чрез Docker Compose
След като образите са успешно качени и описани в конфигурацията, проектът се стартира в бекграунд режим (`-d` / detached) от главната директория `ShoppingList`:
```bash
docker compose up -d
```
*Контейнерите се изграждат в правилния ред, като терминалът потвърждава успешното стартиране на `frontend_container_ioan`, `mongodb` и `backend_container_ioan`.*
